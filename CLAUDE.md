# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`kimrolx` — Kim Roland Berame's personal portfolio. A React 18 + Vite SPA, styled with Tailwind CSS v4, deployed as static assets to Cloudflare Workers. Design intent lives in `DESIGN.md` (Swiss typographic specimen on near-black, one Swiss red) and `PRODUCT.md` (audience, voice, principles) — read them before any visual or content change.

## Ground Rules

- **Never deploy.** Do not run `wrangler deploy` or any publish/release command. Deployment is the owner's call, done manually by them.
- **Never commit, push, or tag** unless explicitly asked in that message. No `git commit`, `git push`, branch creation, or history rewrites on your own initiative.
- **Never force-push.** No `git push --force` / `--force-with-lease` under any circumstance, even if asked — surface the conflict instead.
- **Never hand-edit prerender output.** Files under `dist/` (especially the per-route `dist/<route>/index.html`) are generated by `scripts/prerender.ts`. Change the source (`seo.ts` / the script) and rebuild — never touch `dist/` by hand.
- **Never edit `src/data/` content to invent facts.** Projects, experience, gear, and profile copy are the owner's real record — change wording only when asked, and never fabricate a project, date, metric, or link.
- **Ask before adding dependencies.** Keep the stack lean; propose, don't `npm install` unprompted.
- **Preserve the design system.** Use tokens from `src/index.css` (`@theme`), honor `DESIGN.md`/`PRODUCT.md`. No new hardcoded colors, fonts, or off-brand motion.
- **Keep `seo.ts` consumers in sync.** Any route/meta change must keep `useSEO`, `prerender.ts`, and their tests aligned; run `npm run test` after.
- **Verify before claiming done.** Run `npm run build && npm run lint && npm run test` and confirm they pass before saying a change works — the build runs the prerender, so a broken build ships broken SEO.
- **A11y is non-negotiable.** Every new animation gates on `usePrefersReducedMotion`. Body text ≥4.5:1, large text ≥3:1 (WCAG AA, per `PRODUCT.md`).
- **No `tailwind.config`.** Tailwind v4 config lives only in `src/index.css` `@theme`. Do not add a config file.
- **Assets go in `src/assets/`, imported.** Use `.webp`, reference via `import` so Vite bundles/hashes them. Don't drop files in `public/` and hardcode paths.
- **Don't hand-edit `index.html` head meta for per-route SEO.** Title/description/canonical/OG flow from `seo.ts`; editing `index.html` directly breaks prerender sync.
- **No code comments unless absolutely necessary.** Good code reads clearly through naming and structure. Add a comment only for genuinely non-obvious intent (a workaround, a subtle constraint, a "why not the obvious thing"), never to restate what the code already says.

## Commands

```bash
npm run dev        # Vite dev server
npm run build      # tsc -b && vite build && tsx scripts/prerender.ts
npm run lint       # eslint .
npm run test       # runs seo.test.ts + prerender.test.ts (node --test via tsx)
npm run preview    # preview the production build
```

Run a single test file: `tsx --test src/config/seo.test.ts`

## Deploy

Deployment is a **manual `wrangler deploy`** (Cloudflare Workers Static Assets), NOT `gh-pages` — the `gh-pages` devDependency is stale and unused. `wrangler.toml` serves `./dist` with `not_found_handling = "single-page-application"`, so every unknown path falls back to the SPA. Always `npm run build` before deploying so the prerendered per-route HTML is fresh.

## Architecture

**Routing & shell.** `src/App.tsx` is the single shell: `SmoothScroll` (Lenis) → `EasterEggProvider` → `WipeProvider` wrap three routes — `/` (`Home`), `/now` (`Now`), `/gear` (`Gear`) in `src/pages/`. `Home` composes the section components in `src/sections/` (Hero, About, Experience, Projects, Contact). `TopBar` + `LeftRail` are persistent chrome. `ScrollToTop` resets Lenis scroll on path change; hash anchors are handled per-page.

**Content is data-driven.** All page content lives as typed arrays in `src/data/` (`projects.ts`, `experience.ts`, `gearItems.ts`, `skills.ts`, `archive.ts`, `now.ts`, `profile.ts`), typed against `src/types/index.ts`. To change what the site *says*, edit `src/data/`, not the components.

**SEO — the one cross-cutting system.** `src/config/seo.ts` is the single source of truth for per-route meta (plain data + pure helpers, no DOM). It feeds two consumers that must stay in sync:
- `src/hooks/useSEO.ts` — live `<head>` updates client-side as the SPA navigates.
- `scripts/prerender.ts` — post-build step that copies `dist/index.html` into `dist/<route>/index.html` with title/description/canonical/OG/Twitter tags rewritten, so JS-less social scrapers get the right card. Body is untouched (Google renders the SPA).

Adding or changing a route means updating `ROUTES` in `seo.ts`; the hook, the prerender, and their tests all key off it.

**Styling.** Tailwind v4, configured entirely in `src/index.css` via `@theme` (no `tailwind.config`). Design tokens are CSS custom properties — colors in oklch (`--color-bg`, `--color-ink`, `--color-red`, etc.), `--font-sans` is Schibsted Grotesk (loaded from Google Fonts in `index.html`). Use the token classes (`bg-bg`, `text-ink`, `text-red`), don't hardcode hex. `@/` aliases `src/` (see `vite.config.ts`).

**Motion & a11y.** Motion via `motion` (Framer) and Lenis smooth scroll. `usePrefersReducedMotion` gates everything: reduced motion disables Lenis, resolves reveals to fully-visible, and holds the typewriter greeting. Target is WCAG AA — honor `prefers-reduced-motion` in any new animation.

**Easter egg.** Konami code (`useKonami`) toggles a CRT terminal overlay (`CrtTerminal`, `crtCommands.ts`, `EasterEggProvider`). Self-contained; ignore unless working on it.
